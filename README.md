# libGo

Учебный backend на Go для совместного написания книг.

Идея проекта: пользователи создают книги и дополняют их своими фрагментами. У каждого фрагмента сохраняется автор, а опубликованный текст нельзя редактировать.

Пока реализованы HTTP-сервер, конфигурация через переменные окружения, логирование и подключение к PostgreSQL. Есть миграция таблицы пользователей. Регистрация и работа с книгами — следующие этапы.

## Для запуска

- Go — версия указана в `go.mod`.
- Docker с Docker Compose.
- Утилита `goose` для применения миграций.

Все команды выполняются из корня проекта.

## Настройки

Создай локальный файл настроек:

```bash
cp .env.example .env
```

Заполни `.env` своими значениями:

- `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` — настройки PostgreSQL.
- `DATABASE_URL` — строка подключения приложения.
- `GOOSE_DRIVER=postgres` — тип базы для goose.
- `GOOSE_DBSTRING` — строка подключения для миграций.
- `GOOSE_MIGRATION_DIR=./migrations` — каталог миграций.

Пользователь, пароль и имя базы в строках подключения должны соответствовать настройкам PostgreSQL. При запуске приложения на компьютере используй адрес `127.0.0.1` и порт `5431`, указанный в `compose.yaml`.

Адрес HTTP-сервера задаётся через `HTTP_ADDR`. По умолчанию — `127.0.0.1:8080`.

Настоящий `.env` с паролем не добавляется в Git. В репозитории хранится только `.env.example`.

## Запуск

Запусти Docker и PostgreSQL:

```bash
docker compose up -d postgres
```

Перед первым запуском приложения примени миграции:

```bash
goose up
```

Goose самостоятельно читает `.env`. Команду `goose up` также нужно выполнять после появления новых миграций.

Go-приложение читает переменные окружения, поэтому перед его запуском загрузи настройки в текущий терминал:

```bash
set -a
source .env
set +a
go run ./cmd/api
```

При запуске приложение проверяет подключение к PostgreSQL. Если проверка завершается ошибкой, HTTP-сервер не запускается.

## Проверка

В другом терминале:

```bash
curl http://127.0.0.1:8080/health
```

Ожидаемый ответ:

```json
{"status":"ok"}
```

Если изменил `HTTP_ADDR`, используй свой адрес.

`/health` пока проверяет только то, что HTTP-сервер отвечает. Состояние подключения к базе этот обработчик не проверяет.
